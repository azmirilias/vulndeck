About

A small, honest instrument for vulnerability decisions.

{{ SITE.SITE_NAME }} answers three questions fast: what is being exploited right now, how likely is the rest to be exploited, and which of my dependencies are affected.

Design constraints

This is a single-process Python service with a SQLite database, server-rendered HTML and one small stylesheet. No JavaScript framework, no client-side data fetching, no third-party analytics, no external font requests. Pages are complete HTML on first byte, which is good for readers, good for search engines and cheap on a 1 GB VPS.

Where the data comes from

Only public, machine-readable sources with terms that permit reuse: CISA KEV, EPSS, the GitHub Advisory Database, CVE.org, NVD and publisher RSS feeds. Every connector is one function in app/ingest.py, and every run is logged publicly on the sources page.

Scoring, stated plainly

CVSS describes severity, not urgency. VulnDeck therefore leads with two signals that describe reality: KEV membership (exploitation observed) and EPSS (probability of exploitation in the next 30 days). A CVSS 9.8 with no exploitation activity is not the same operational problem as a CVSS 7.5 that ransomware crews are already using.

Independence & provenance

{{ SITE.SITE_NAME }} is an independent project written from scratch: no code, markup, styling, database schema or copy was taken from another threat-intelligence product. It is not a fork, mirror or derivative of MANTIS, OpenCTI, MISP, IntelOwl or any other workbench, and it claims no affiliation with their authors.
